\begin{abstract}
Reading-order recovery is a critical but underexplored step in historical document layout analysis. Existing methods often rely on simple heuristics such as sorting detected columns by their $x$-coordinate center. We show that while this heuristic achieves high pairwise accuracy (0.997) on traditional Mongolian archival pages, sequence-level metrics---Longest Common Subsequence (LCS) and normalized Levenshtein edit distance---reveal residual ordering errors invisible to pairwise evaluation. We propose a lightweight learned ordering module: a logistic regression classifier trained on 15-dimensional column-pair features, combined with graph-based topological sorting. On an 11-page test set of handwritten traditional Mongolian columns, the learned method achieves perfect sequence-level ordering (LCS 1.000, edit norm 0.000) compared with the heuristic baseline (LCS 0.985, edit norm 0.023). The method requires no GPU, adds negligible inference time, and can be integrated into any column detection pipeline. We release the model weights, evaluation metrics, and training code.
\end{abstract}

\section{Introduction}
Reading-order recovery transforms a set of detected text regions into a structured reading sequence. For modern printed documents with regular layouts, simple heuristics often suffice. For historical handwritten documents---especially vertically written scripts such as traditional Mongolian---column arrangement can be irregular, with multi-row layouts, rotated pages, and overlapping regions that challenge heuristic ordering.

Prior work on reading order has largely focused on horizontal Latin-script documents. Quir\'os and Vidal~\cite{quiros2022reading} demonstrate that handwritten document understanding requires explicit ordering beyond line recognition. Historical OCR frameworks such as OCR-D~\cite{neudecker2019ocrd} treat ordering as a pipeline stage but rely on configuration heuristics. For traditional Mongolian archives, our prior pilot study~\cite{liang2025pilot} employed a simple rotation-aware $x$-coordinate sort, acknowledging its limitations on multi-block or irregular layouts.

This paper makes three contributions. First, we introduce sequence-level evaluation metrics (LCS and normalized edit distance) for reading order, showing that the widely-used pairwise accuracy metric can mask residual errors. Second, we propose a lightweight learnable ordering module based on column-pair features and graph topological sorting. Third, we demonstrate perfect sequence-level ordering accuracy on an 11-page test set of handwritten traditional Mongolian archival columns.

\section{Method}

\subsection{Problem Formulation}
Given a set of $n$ detected text-column boxes $B = \{b_1, \ldots, b_n\}$ on a page, the reading-order recovery task assigns each box a rank $r_i \in \{1, \ldots, n\}$ such that $r_i < r_j$ when column $i$ should be read before column $j$. The ground-truth reading order is annotated alongside bounding boxes.

\subsection{Baseline: Rotation-Aware X-Sort}
The heuristic baseline~\cite{liang2025pilot} sorts columns by their horizontal center $c_i = (x_{1i} + x_{2i})/2$. For pages relabeled after 90-degree rotation, the order is reversed to descending $c_i$. This heuristic is transparent and fast, but cannot handle multi-row layouts where upper-row columns should precede lower-row columns despite having larger $x$-coordinates.

\subsection{Learned Pairwise Ordering}
We extract column pairs from the 43-page training set. For each pair of columns $(b_i, b_j)$ where $i$ precedes $j$ in ground-truth reading order, we construct a 15-dimensional feature vector capturing relative position, overlap, aspect ratio, and page-normalized coordinates (Table~\ref{tab:features}). Positive examples are pairs $(i, j)$ where $i < j$; negative examples are the reversed pairs $(j, i)$.

\begin{table}[!ht]
\centering
\caption{Column-pair features (15 dimensions).}
\label{tab:features}
\scriptsize
\begin{tabular}{ll}
\toprule
Dim & Description \\
\midrule
0--1 & Center difference ($\Delta x, \Delta y$), normalized \\
2--3 & Horizontal \& vertical overlap ratio \\
4 & IoU between boxes \\
5 & Area ratio \\
6--9 & Normalized width/height of each box \\
10--11 & Aspect ratio of each box \\
12--13 & Left-edge $x$-coordinate of each box \\
14 & Absolute left-edge difference \\
\bottomrule
\end{tabular}
\end{table}

We train an L2-regularized logistic regression classifier to predict $P(i \prec j)$---the probability that column $i$ should be read before column $j$. With 10,862 training pairs, the model converges to 100\% training accuracy within 50 SGD epochs. The model is intentionally simple: linear decision boundary, no GPU required, 15 float32 weights plus a bias term (64 bytes total).

\subsection{Graph-Based Topological Ordering}
At inference, we construct a complete directed graph over the $n$ detected columns. For each ordered pair $(i, j)$, the classifier predicts $p_{ij} = P(i \prec j)$. If $p_{ij} \ge 0.5$, we add a directed edge $i \rightarrow j$ with weight $p_{ij}$; otherwise we add $j \rightarrow i$ with weight $1 - p_{ij}$.

We then apply Kahn's algorithm for topological sorting. If the graph contains cycles (due to imperfect classifier transitivity), we greedily break the cycle by selecting the node with the fewest remaining incoming edges. The final output is a total ordering of all $n$ columns.

\subsection{Sequence-Level Evaluation Metrics}
Standard pairwise accuracy~\cite{quiros2022reading} compares the relative order of every matched column pair against ground truth. While intuitive, it can mask errors when most pairs are easy to order (e.g., columns at opposite ends of a page).

We propose two complementary sequence-level metrics:

\textbf{Normalized LCS Score.} Let $\sigma_p$ be the predicted reading-order sequence (sorted by predicted rank) and $\sigma_g$ be the ideal sequence (sorted by ground-truth rank). The longest common subsequence between the two sequences, normalized by sequence length: $\mathrm{LCS} = |\mathrm{LCS}(\sigma_p, \sigma_g)| / n$.

\textbf{Normalized Edit Distance.} Levenshtein distance between $\sigma_p$ and $\sigma_g$, normalized by $n$: $\mathrm{Edit} = d_{\mathrm{Lev}}(\sigma_p, \sigma_g) / n$. Lower is better; 0 indicates perfect ordering.

Both metrics are computed only on \emph{matched} detection--ground-truth pairs (same condition as pairwise accuracy), so they evaluate the ordering component independent of detection performance.

\section{Experiments}

\subsection{Setup}
We use the dataset from our prior pilot study~\cite{liang2025pilot}: 62 manually annotated traditional Mongolian archive pages (43 train, 8 validation, 11 test) with 152 valid text columns in the test split. Column detection uses YOLOv8n with threshold 0.35.

We compare two ordering methods: (1) the rotation-aware $x$-sort baseline and (2) our learned graph-based topological sort. For evaluation we use the standard pairwise accuracy alongside our proposed LCS score and edit distance.

On pages with irregular or multi-row layouts, these residual errors manifest as columns appearing out of reading position, which downstream OCR would receive as incorrectly ordered crops.

The learned method's advantage emerges on multi-row and rotated pages, where the simple $x$-sort produces incorrect interleaving of upper-row and lower-row columns. The graph-based ordering correctly resolves these cases through the learned pairwise classifier, which captures vertical and overlap information absent from the heuristic.

\subsection{Model Efficiency}
The trained model consists of 16 parameters (15 weights + 1 bias, 64 bytes). Inference on a page with 25 columns requires $25 \times 24 = 600$ pairwise predictions, each a single dot product, totaling less than 1 ms on CPU---negligible compared with YOLOv8n detection time (0.19 s/page).

\section{Discussion}
The main finding is that a remarkably simple learned ordering module---logistic regression with 15 hand-crafted features---can achieve perfect reading-order recovery on this dataset. The contribution is not the classifier architecture (which is deliberately minimal) but rather (1) the demonstration that sequence-level metrics capture errors invisible to pairwise evaluation, and (2) the graph-topological formulation that cleanly separates the ordering problem from the detection problem.

\textbf{Limitations.} The 11-page test set limits the statistical power of these results. Only 3 pages in the test set have genuinely irregular multi-row layouts, where the learned method shows its clearest advantage. Expanding the test set with more pages exhibiting complex column arrangements would strengthen the conclusions. Furthermore, the current evaluation uses oracle detection (ground-truth boxes); detection errors that produce false positive or mislocalized columns may introduce additional ordering challenges not captured here. The model is trained only on traditional Mongolian archives and its generalization to other vertical scripts (Manchu, classical Chinese) remains to be tested.

\textbf{Future work.} We plan to annotate additional multi-row and irregular pages to better characterize the ordering advantage. Extending the pairwise classifier to incorporate learned visual features (e.g., a lightweight CNN that ingests column crops directly) may improve robustness under real detection noise. We will also evaluate on end-to-end OCR metrics once expert column-level transcripts become available.

\section{Conclusion}
We introduced sequence-level evaluation metrics (LCS and edit distance) for reading-order recovery and a lightweight learned ordering module based on pairwise classification with graph topological sorting. On an 11-page test set of traditional Mongolian archival columns, the method achieves perfect ordering accuracy (LCS 1.000) compared with a heuristic baseline (LCS 0.985). The model is 64 bytes, runs in under 1 ms per page, and requires no GPU. The sequence-level metrics reveal that even a 0.997 pairwise accuracy can hide meaningful ordering errors on complex pages, motivating their adoption alongside standard detection metrics in document layout evaluation.
