\begin{abstract}
Reading-order recovery is a critical pipeline stage in historical document layout analysis, typically addressed by sorting detected columns by horizontal position. We investigate whether a learned ordering module---logistic regression on column-pair features with graph-based topological sorting---can improve over this heuristic on traditional Mongolian archival pages. We find a sharp oracle-to-real gap: the learned method achieves perfect sequence-level ordering (LCS 1.000, edit 0.000) on ground-truth boxes, but degrades to near-random performance (pairwise 0.428, LCS 0.421) on real YOLOv8n detections of the same pages. In contrast, the simple $x$-coordinate sort is unaffected (pairwise 0.996, LCS 0.992). We introduce two sequence-level evaluation metrics---normalized LCS and Levenshtein distance---that capture residual errors invisible to standard pairwise accuracy, and identify detection noise as the fundamental bottleneck for practical learned reading-order recovery. These findings motivate detector-aware ordering and end-to-end joint optimization for document layout pipelines.
\end{abstract}

\section{Introduction}
Reading-order recovery transforms detected text regions into a reading sequence. For historical handwritten documents---especially vertically written scripts such as traditional Mongolian---column arrangement can be irregular, with multi-row layouts creating ambiguous ordering.

Prior work addresses ordering primarily in Latin-script contexts~\cite{quiros2022reading,neudecker2019ocrd}. Our prior pilot study~\cite{liang2025pilot} used a rotation-aware $x$-coordinate sort. The standard metric is pairwise reading-order accuracy~\cite{quiros2022reading}: the fraction of column pairs with correct relative order.

We ask: can a lightweight learned ordering module improve over this simple heuristic? We find a nuanced answer: \emph{yes} under oracle (perfect) detection; \emph{no} under real detection. This oracle-to-real gap---1.000 LCS with GT boxes vs.\ 0.421 with YOLO detections---is our primary contribution. Secondary contributions include sequence-level evaluation metrics and a 64-byte classifier achieving perfect oracle ordering.

\section{Method}

\subsection{Heuristic Baseline and Learned Ordering}
\textbf{X-sort.} Sort columns by horizontal center $c_i=(x_{1i}+x_{2i})/2$; reverse for 90$^\circ$-rotated pages.

\textbf{Pairwise classifier.} For each column pair $(i,j)$ where $i \prec j$ in ground truth, extract 15 features: center differences $(\Delta x,\Delta y)$, overlap ratios, IoU, area ratio, normalized dimensions, aspect ratios, and edge positions (all page-normalized). Train L2-regularized logistic regression (SGD, 200 epochs) on 10,862 pairs from 43 training pages, achieving 100\% accuracy.

\textbf{Graph topological sort.} At inference, construct a complete digraph over $n$ columns. For each pair $(i,j)$, if $P(i \prec j) \ge 0.5$, add edge $i \to j$; otherwise $j \to i$. Kahn's algorithm with greedy cycle breaking produces the final ordering. Model size: 64 bytes (16 float32 parameters).

\subsection{Sequence-Level Evaluation}
Standard pairwise accuracy masks errors when most pairs are trivially ordered. We add:

\textbf{Normalized LCS:} $|\mathrm{LCS}(\sigma_p,\sigma_g)|/n$, where $\sigma_p,\sigma_g$ are predicted and GT reading sequences of matched columns. Range: [0,1]; higher is better.

\textbf{Normalized Edit Distance:} $d_{\mathrm{Lev}}(\sigma_p,\sigma_g)/n$. Range: [0,$\infty$); lower is better.

Both metrics use only matched detection--GT pairs, isolating ordering from detection quality.

\section{Experiments}
Dataset: 62 annotated traditional Mongolian archive pages (43 train, 8 val, 11 test)~\cite{liang2025pilot}, plus 43 expansion test pages from additional folders. Column detection: YOLOv8n, threshold 0.35. Oracle condition: GT boxes substitute for detections.

\section{Discussion}
We identify two mechanisms behind the oracle-to-real gap. \textit{False positive detections} add spurious graph nodes absent from training. \textit{Boundary imprecision} perturbs fine-grained geometric features, flipping edge predictions. A single flipped edge cascades through topological sort.

\textbf{Implications.} (1) Ordering should be detector-aware: trained on detector outputs, not GT boxes. (2) The $x$-sort's robustness suggests geometric heuristics retain value as fallback methods. (3) Sequence-level metrics should complement pairwise accuracy in reading-order evaluation.

\textbf{Limitations.} Multi-row pages are underrepresented. YOLO-retrained classifier used greedy box matching, introducing label noise. End-to-end joint training of detector + ordering module is left to future work.

\section{Conclusion}
We demonstrate a sharp oracle-to-real gap in learned reading-order recovery: perfect with GT boxes, near-random with real detections. The gap identifies detection noise as the primary bottleneck, motivating detector-aware training and end-to-end optimization. We introduce sequence-level ordering metrics (LCS, edit distance) that capture errors invisible to pairwise accuracy, and recommend their adoption in document layout evaluation.
